# FraudGuard frontend

React 19 single-page app (Vite 8, React Router 8, plain CSS, no UI library). It talks **only** to the
gateway's `/api/*` routes (docs/contracts.md §8, §8.1): never to a scan service, RabbitMQ or an
`/internal` route.

| Route                 | Who    | What                                                                                                                   |
| --------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------- |
| `/login`, `/register` | anyone | Registration signs straight in.                                                                                        |
| `/`                   | user   | Wallet, deposit, transfer form with the **Risk profile** selector, live tracker of the last transfer, recent activity. |
| `/transactions`       | user   | History with status and tier badges, status filter, cursor paging, per-transaction scan details and status history.    |
| `/alerts`             | user   | Alerts; OTP entry for `OTP_STEP_UP` alerts still `AWAITING_OTP`.                                                       |
| `/admin`              | admin  | Manual review queue (approve/reject, unfreeze after a rejection) and the active tier policy with a reload button.      |

## How it behaves

- **Live status.** A flagged transfer is followed by polling `GET /api/transactions/{id}`: every 2 s, backing
  off to 10 s, stopping at a resting status (`APPROVED`, `BLOCKED`, `AWAITING_OTP`, `ACCOUNT_FROZEN`).
- **Risk profiles.** Transfers without features get a neutral vector and are approved instantly, so the form
  offers real dataset rows (`src/demo/sampleFeatures.json`, generated by `tools/make_demo_samples.py`):
  _Normal_, _Suspicious_ (deep-scan MEDIUM/HIGH, so notify or OTP) and _Known fraud_ (CRITICAL, so freeze).
  Choosing a sample pre-fills its original amount, because `Amount` is one of the model's features.
- **Safe retries.** Each transfer attempt carries one `Idempotency-Key`; after a network error or 5xx,
  "Retry send" reuses it, so a retry never creates a second transfer.
- **Session.** The JWT is kept in `sessionStorage` and dropped at `exp` or on any `401` (there are no refresh
  tokens, §0.4). Admin-only UI is cosmetic: the services enforce roles.

## Run

```bash
npm ci
GATEWAY_URL=http://localhost:8080 npm run dev   # http://localhost:5173, /api proxied to the gateway
npm test                                       # Vitest + Testing Library (jsdom)
npm run lint                                   # ESLint (react-hooks) + Prettier
npm run build                                  # dist/
```

In compose the image is built and served behind the gateway: open `http://localhost:${GATEWAY_HOST_PORT}`.

## Image

Multi-stage: `node:22-alpine` builds the bundle; `nginxinc/nginx-unprivileged` (uid 101) serves it on
**8081** with SPA fallback, a strict Content-Security-Policy, year-long caching for hashed `/assets/*`
(never for 404s), `no-cache` for `index.html`, and `GET /health`.

| Variable                | When                  | Default                 | Purpose                                                          |
| ----------------------- | --------------------- | ----------------------- | ---------------------------------------------------------------- |
| `VITE_API_BASE_URL`     | build (`--build-arg`) | `/api`                  | API base; same origin through the gateway.                       |
| `NGINX_CSP_CONNECT_SRC` | runtime               | `'self'`                | Extra CSP `connect-src` sources if the API is on another origin. |
| `GATEWAY_URL`           | `npm run dev` only    | `http://localhost:8080` | Where the dev server proxies `/api`.                             |

A static site has no `/metrics`; its traffic is measured at the gateway.
